## 1. Problem Statement
Imágenes Docker con usuario root aumentan vectores de ataque; el modelo tradicional de hilos por petición agota la memoria bajo concurrencia masiva; y los apagados abruptos (`SIGTERM`) corrompen transacciones en vuelo y dejan bloqueos huérfanos en el outbox.

## 2. Decision Matrix
| Directiva | Regla | Especificación Técnica |
| :--- | :---: | :--- |
| **`MUST`** | `TRX-01` | Construcción Docker multi-stage: compilación en `gradle:8-jdk21-alpine`, imagen final en `eclipse-temurin:21-jre-alpine` (< 180 MB). |
| **`MUST`** | `TRX-01` | Ejecución obligatoria bajo usuario sin privilegios `nonroot` (UID 10001, GID 10001). |
| **`MUST`** | `TRX-01` | Habilitar Virtual Threads en Spring Boot (`spring.threads.virtual.enabled=true`). |
| **`MUST`** | `TRX-01` | Colector de basura Generational ZGC mediante flags JVM: `-XX:+UseZGC -XX:+ZGenerational` (pausas STW < 1 ms). |
| **`MUST`** | `TRX-01` | Límite de memoria adaptativo: `-XX:MaxRAMPercentage=75.0`. |
| **`MUST`** | `TRX-01` | Apagado ordenado (*Graceful Shutdown*): `server.shutdown=graceful` y `spring.lifecycle.timeout-per-shutdown-phase=30s`. |
| **`MUST`** | `SHR-03` | Envoltura de contexto (`ExecutionContextFilter` / `runWith`) con limpieza incondicional en bloque `finally` para evitar fugas de `ThreadLocal`. |
| **`NEVER`** | `TRX-01` | Ejecutar el contenedor como usuario `root` o incluir herramientas de compilación/debug en el runtime final. |

## 3. Canonical Runtime Topology
```text
ETAPA 1 (Builder):  gradle:8-jdk21-alpine (Compilación aislada) ──► Genera app.jar
                                                                           │
ETAPA 2 (Runtime):  eclipse-temurin:21-jre-alpine (~180 MB) ◄──────────────┘
                    ├── Usuario: nonroot (UID 10001)
                    ├── Virtual Threads: spring.threads.virtual.enabled=true
                    ├── Garbage Collector: -XX:+UseZGC -XX:+ZGenerational
                    ├── Memoria: -XX:MaxRAMPercentage=75.0
                    └── Parada Limpia: server.shutdown=graceful (30s)
```

## 4. Trade-Offs & Mitigations
* **Peligro de Fuga en ThreadLocal con Virtual Threads:**
  * *Mitigación:* Pruebas de integración automatizadas validan que los filtros limpian `ExecutionContextHolder` en `finally`.
