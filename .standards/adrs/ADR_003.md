## 1. Problem Statement
El coste de inspección de pila nativa (`fillInStackTrace()`) en Java consume entre 90% y 95% de CPU al lanzar excepciones convencionales en flujos de negocio alternativos. Adicionalmente, respuestas dispares filtran detalles internos y complican el consumo API.

## 2. Decision Matrix
| Directiva | Regla | Especificación Técnica |
| :--- | :---: | :--- |
| **`MUST`** | `ERR-01` | Toda excepción de negocio hereda obligatoriamente de `BaseException`. |
| **`MUST`** | `ERR-02` | `writableStackTrace = false` para errores de negocio (`category.capturesDiagnostics() == false`). Coste cero de asignación en JVM. |
| **`MUST`** | `ERR-07` | Reutilizar exclusivamente el catálogo cerrado de 7 excepciones de `shared.domain.exception` parametrizadas con `<Subdominio>Error`. |
| **`MUST`** | `SHR-04` | Gramática de códigos: `[MODULO]_[ENTIDAD]_[MOTIVO]` (módulos), `[ENTIDAD]_[CAMPO]_[REGLA]` (validación sintáctica). |
| **`MUST`** | `INP-03` | `GlobalExceptionHandler` unifica respuestas al contrato inmutable `ErrorResponse(status, code, detail, errors)`. |
| **`MUST`** | `INP-03` | Errores imprevistos (`500`) capturan stack trace en log interno `ERROR` pero se enmascaran al cliente como `"An unexpected error occurred"`. |
| **`NEVER`** | `ERR-01` | Lanzar `RuntimeException` planas o no tipadas en dominio y aplicación. |
| **`NEVER`** | `ERR-07` | Crear subclases personalizadas de excepción dentro de los módulos de dominio. |
| **`NEVER`** | `ERR-05` | Bloques `catch` vacíos o que silencien la excepción sin relanzar o encadenar causa. |

## 3. Canonical Hierarchy
```text
RuntimeException (JDK)
 └── BaseException (abstracta, writableStackTrace condicional)
      ├── ResourceNotFoundException [404]  ──► writableStackTrace: false
      ├── ConflictException         [409]  ──► writableStackTrace: false
      ├── ValidationException       [400]  ──► writableStackTrace: false
      ├── ForbiddenException        [403]  ──► writableStackTrace: false
      ├── UnauthenticatedException  [401]  ──► writableStackTrace: false
      ├── InfrastructureException   [500]  ──► writableStackTrace: true (enmascarado en API)
      └── ExternalServiceException  [500]  ──► writableStackTrace: true (enmascarado en API)
```

## 4. Trade-Offs & Mitigations
* **Ausencia de Stack Trace en Errores de Negocio:** No se puede inspeccionar la pila para excepciones funcionales.
  * *Mitigación:* Los errores funcionales son comportamientos normales; el código tipado (`code()`) y log `WARN` proveen diagnóstico completo.
